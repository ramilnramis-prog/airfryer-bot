# Scene-05 — план слоёв поверх approved baseplate-B

Статус: **baseplate-B зафиксирован как единственный approved** (см.
`generated/scene-05-real-baseplate/baseplate-selection.json`). A и C —
rejected alternatives, файлы не удалены. Новый baseplate не генерируется,
transform продукта (`scale=0.56, rotation_deg=-1.0, translate=(137.24,20.48)`)
не меняется — все следующие слои работают ТОЛЬКО поверх уже существующего
`baseplate-B.png`.

## Опорные координаты (холст 720×1280, привязаны к baseplate-B по SHA256
в `zones-manifest.json`)

- **product_bbox** (весь силуэт формы на холсте B): `(145, 28, 595, 380)`
- **left handle bbox**: `(190, 44, 275, 100)`
- **right handle bbox**: `(549, 166, 595, 259)`

Все зоны ниже проверены визуальным наложением на `baseplate-B.png`
(`approved-B/zones-overlay-check.png`) — это геометрическая разметка
(прямоугольники/эллипс), не генеративный контент.

## Порядок слоёв (сверху вниз в файловой системе = снизу вверх при рендере)

```
5. EFFECTS        contact_shadow (тень) + steam_zone (пар)
4. FRONT_HAND     front_hand_left / front_hand_right (пальцы поверх ручек)
3. PRODUCT        baseplate-B (ЗАМОК — уже собран, не трогаем)
2. BACK_HAND      back_hand_left / back_hand_right (кисти позади ручек)
1. BACKGROUND     уже часть baseplate-B (реальный DE'MIAND + корзина)
```

Поскольку BACKGROUND и PRODUCT уже сведены в единый `baseplate-B.png`,
дальнейшая композиция технически идёт как **добавление новых слоёв ПОВЕРХ
готового растра** (BACK_HAND рисуется первым, вставляется под изображение
там, где это физически заходит за форму — на практике для растрового
baseplate это означает: back_hand добавляется в области, которые НЕ
перекрывают product_bbox, чтобы не заходить поверх уже отрендеренной формы;
если требуется точное «под формой», следующий шаг должен работать через
исходные RGBA-слои (`SceneLayers`) заново, а не поверх плоского PNG —
см. «Ограничения» ниже).

## 1. BACK HAND (кисти позади ручек)

| Зона | bbox | Назначение |
|---|---|---|
| `back_hand_left` | `(95, 70, 210, 260)` | кисть тянется снизу-слева вверх к левой ручке |
| `back_hand_right` | `(540, 190, 660, 340)` | кисть тянется снизу-справа вверх к правой ручке |

Требования: женские руки, без украшений (кольца/часы/браслеты), светлая
кожа, ухоженные ногти без яркого лака — по Visual Bible. Реального фото
пока нет (единственная реальная рука в материалах — мужская, из
`real-v1/motion/grip_motion_master.png`, используется ТОЛЬКО как motion/grip
reference, не как источник пикселей).

## 2. FRONT HAND (пальцы поверх ручек)

| Зона | bbox | Назначение |
|---|---|---|
| `front_hand_left` | `(178, 30, 285, 78)` | большой палец/сустав поверх верхней части левой ручки |
| `front_hand_right` | `(540, 150, 600, 195)` | большой палец/сустав поверх верхней части правой ручки |

Правило `product_lock.json.occlusion_rules`: перекрытие каждой ручки ≤ 60%
площади, силуэт ручки должен оставаться читаемым для QA. front_hand_left
перекрывает верхние ~34px из 56px высоты left handle bbox (~60%, на
границе допуска — при реальной генерации/фото проверить фактическое
перекрытие через `masks.check_contact_zones`).

## 3. FOOD LAYER

| Зона | bbox | Назначение |
|---|---|---|
| `food_layer` | `(205, 150, 560, 345)` | внутренняя ребристая область дна формы |

3 куриных бёдрышка + дольки картофеля (по campaign spec), укладываются
внутри этой зоны. Слой композится ПОВЕРХ product (форма уже видна, еда
«лежит в ней»), но НЕ имеет права редактировать альфу/пиксели самой формы
— проверяется тем же `product_lock_validator` (еда не должна пересекать
product mask за пределами food_layer, иначе — риск закрыть ручки/борт).

## 4. SOFT SHADOW / CONTACT SHADOW

| Зона | форма | Назначение |
|---|---|---|
| `contact_shadow` | эллипс `(210, 360, 510, 412)`, центр (360, 386) | мягкая тень формы на задней кромке/стенке корзины |

Уже используется в текущем `baseplate-B.png` (сгенерирована в момент
сборки как `_shadow_overlay(canvas, 360, 386)`) — при добавлении новых
слоёв тень остаётся как есть, повторно не рассчитывается.

## 5. LIGHT STEAM

| Зона | bbox | Назначение |
|---|---|---|
| `steam_zone` | `(250, 0, 520, 130)` | лёгкий пар над формой |

Пар — полупрозрачный overlay (как в `compositor/rigid_animation.py:
_steam_overlay`, процедурный, без AI). Не должен закрывать ручки или
верхний край еды; верхняя треть зоны частично перекрывает посторонний
предмет фона (лист бумаги/рецепт в кадре) — фон допустимо «зачистить» перед
финальной версией (background cleanup, не трогая сам аэрогриль/товар).

   интенсивность подбирается на глаз при монтаже.

## Ограничения текущего шага

- Все зоны — прямоугольники/эллипс, построенные вручную по сетке и сверенные
  визуальным наложением; это план/маски для СЛЕДУЮЩЕГО шага генерации, а не
  готовые пиксели рук/еды.
- Технически для точной покадровой композиции (особенно back_hand «под
  формой») эффективнее пересобрать сцену из исходных RGBA-слоёв
  (`SceneLayers` + `layer_compositor.compose`), а не поверх уже
  сплющенного `baseplate-B.png` — `baseplate-B.png` фиксирует ФОН+ТОВАР
  как эталон для сверки, а не обязательный рабочий холст для дальнейшей
  правки.
- Никаких новых вызовов OpenAI/Higgsfield на этом шаге не выполнялось.
