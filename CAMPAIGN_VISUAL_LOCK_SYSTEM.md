# Campaign-level visual continuity locks

Две разные вещи легко перепутать: то, что зафиксировано **навсегда для всех
кампаний**, и то, что зафиксировано **только внутри одной кампании**. Этот
документ разделяет их явно и описывает, как это проверяется.

## 1. Глобальный неизменяемый канон — только один

`product_canon: real-product-v1` — единственный элемент, постоянный на ВСЕХ
кампаниях и роликах: реальная силиконовая форма (арт. 1931921872), реальные
пиксели, истинная геометрия ручек, короткая горизонтальная прорезь, цвет,
пропорции, рифлёное дно.

- Источник истины: `assets/product-lock/airfryer-silicone-form/product_asset_manifest.json`
- Форма НИКОГДА не перерисовывается, не заменяется, не подгоняется генеративно.
  Компоновка идёт через product-locked compositing
  (`api/media_pipeline/compositor/`), а не через генерацию формы в кадре.
- Старая (некорректная) геометрия ручек помечена `legacy_incorrect_product_geometry`,
  `allowed_for_product_lock_source: false` и никогда не используется как источник
  геометрии — ни в этом канона, ни в reference library ниже.

Всё остальное — **НЕ глобальный канон**.

## 2. Reference library — не канон, а материал для выбора

`assets/reference-library/` — библиотека референсов, из которой каждая НОВАЯ
кампания выбирает СВОЙ набор: руки, персонаж, аэрогриль, кухня, одежда, свет,
еда, камера/стиль. Структура:

```
assets/reference-library/
  hands/manifest.json
  people/manifest.json
  airfryers/manifest.json
  kitchens/manifest.json
  clothing/manifest.json
  lighting/manifest.json
  grip-examples/manifest.json
  compositions/manifest.json
  food-examples/manifest.json
  reference_library_index.json   ← сводный список всех записей
```

Каждая запись — это **указатель** (id, source_path, sha256, type, description,
suitable_uses, restrictions, `approved_for_reference_only: true`), а НЕ копия
бинарника. Оригиналы остаются на исходных путях (вне git — большие фото/кадры
не копировались в репозиторий; два уже отслеживаемых реальных кадра из
real-product-v1 shoot процитированы по их существующему пути в репозитории,
без повторного копирования).

Правила:

- Ни один элемент reference library не является геометрией продукта. Даже
  когда на фото видна форма — это фото каталогизировано по кухне/рукам/аэрогрилю
  вокруг неё, а не по форме.
- Фото, где сама форма имеет устаревшую геометрию (`cta.png`, `h1.png`,
  `place.png` и т.п.), помечены restriction-текстом: "никогда не использовать
  как источник геометрии/силуэта, только сцена/рука/кухня вокруг".
- `forma_6angles.png` (контрольный лист 6 ракурсов старой геометрии) —
  единственный файл, исключённый из всех 9 категорий: это не сцена, а
  технический product turnaround старого (замененного) канона; хранится как
  исторический артефакт, никуда не назначен.
- Один и тот же файл может встречаться в НЕСКОЛЬКИХ категориях (например,
  фото женщины у раковины подходит и под `people`, и под `clothing`, и под
  `kitchens`) — это ожидаемо: reference library каталогизирует *пригодность*,
  а не право собственности одной категории на файл.

## 3. Campaign Visual Lock — фиксация ВНУТРИ одной кампании

Для каждой новой кампании создаётся
`content/autopilot/<campaign_code>/campaign_visual_lock.json` с полями:

| Поле | Смысл |
|---|---|
| `campaign_code`, `content_code` | идентификаторы кампании/ролика |
| `product_canon` | всегда `"real-product-v1"` |
| `hands_reference` | выбранный для ЭТОЙ кампании набор рук (id из reference library) |
| `person_reference` | выбранный персонаж |
| `airfryer_reference` | выбранный аэрогриль |
| `kitchen_reference` | выбранная кухня |
| `clothing_reference` | выбранная одежда |
| `lighting_reference` | выбранная схема света |
| `food_reference` | выбранное блюдо (может отличаться по сценам, см. ниже) |
| `camera_style` | ракурс/движение камеры кампании |
| `locked_for_all_scenes` | всегда `true` |
| `shared_across_hooks` | всегда `true` |
| `allowed_scene_changes` | что можно менять между сценами (наклон, пена, эмоция...) |
| `forbidden_continuity_changes` | что менять нельзя ни при каких условиях внутри кампании |

Пример уже созданного файла:
`content/autopilot/coating-protect-2026-07/campaign_visual_lock.json` — там
выбор кампании (по уже существующим scene-specs этой кампании, ничего не
придумано заново): реальный аэрогриль DE'MIAND, кухня Style Anchor (белый
кабанчик + серо-бежевая столешница), одна и та же женщина/кардиган во всех
сценах, дневной свет слева, блюдо — 3 куриных бедра + картофель.

Visual Director при проверке кампании смотрит:

- те же руки во всех сценах;
- тот же аэрогриль;
- тот же персонаж;
- та же одежда;
- та же кухня;
- тот же свет;
- неизменный real-product-v1.

## 4. Между РАЗНЫМИ кампаниями — разнообразие разрешено и ожидаемо

Кампания B может выбрать полностью другой набор (другие руки, другой
аэрогриль, другая кухня, другой персонаж, другая одежда, другой свет), пока
внутри самой кампании B этот новый набор остаётся зафиксированным на все её
сцены. `product_canon` при этом не меняется никогда.

```
VIDEO CAMPAIGN A: hands A, airfryer A, kitchen A, person A, clothing A, lighting A
VIDEO CAMPAIGN B: hands B, airfryer B, kitchen B, person B, clothing B, lighting B
                   (независимый выбор, ПРОДУКТ — тот же real-product-v1)
```

## 5. Один ролик = три хука

Один `content_code` = одно основное видео (один сюжет, один storyboard, один
`campaign_visual_lock`, один product_canon) и три варианта хука A/B/C. Хуки
могут отличаться ТОЛЬКО:

- первыми 1–3 секундами;
- первым кадром;
- первой фразой;
- on-screen caption;
- voice-over hook.

Основное тело ролика и весь выбранный визуальный набор — общие для всех трёх
хуков (`campaign_visual_lock.json → hooks.shared_main_body: true`,
`shared_visual_lock` указывает на тот же файл).

## 6. Еда — сцено-специфична

В отличие от рук/персонажа/аэрогриля/кухни/одежды/света, еда МОЖЕТ отличаться
по сценам одной кампании (сцена без еды → сцена с сырой едой → сцена с
готовой едой), при этом конкретное блюдо (например, "3 бедра + картофель")
всё равно фиксируется в scene-specs кампании, чтобы не появлялось разных
блюд в разных сценах ОДНОГО ролика без причины.

## 8. Стоимость и сеть

Вся работа этой системы — чтение/запись локальных JSON и локальная обработка
изображений (PIL, downscale, thumbnails). Ни OpenAI Images/Vision, ни
Higgsfield, ни любые другие платные или сетевые API не вызываются.
